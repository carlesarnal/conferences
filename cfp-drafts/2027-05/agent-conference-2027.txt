What topic would you like to speak about?
Agent sprawl: discovering agents and checking their declared contracts across teams

What knowledge, lessons, or examples could the audience take away?
As teams add AI agents, finding an endpoint is only part of the problem. They
also need to understand what each agent advertises, how changes affect callers,
and which checks belong in registry publication versus application deployment.

Using a tested Quarkus example, an MCP weather tool feeds an A2A summarizer and
translator through registry-discovered endpoints. We remove a declared skill,
inspect the rejected Agent Card publication and unchanged accepted registration,
then rerun the workflow and publish a compatible addition. The application owns
the sequence. Metadata compatibility does not prove remote implementation behavior.

Attendees will leave with a checklist of decisions to make before expanding
agent adoption: where capability information lives, how contract changes are
reviewed, what consumers must check, and which integration and behavioral tests
are needed alongside a registry.
