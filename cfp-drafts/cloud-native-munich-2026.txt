SUBMISSION 1: Real-Time Lakehouse
----------------------------------

Session Title:
From Database to Lakehouse in Real-Time: CDC, Kafka, Apicurio, and Apache Iceberg

Description:
Batch ETL runs nightly. Analysts query stale data. ML models train on yesterday's features. The streaming-first lakehouse replaces that with real-time pipelines built entirely with open-source tools on Kubernetes.

This talk demos: Debezium captures PostgreSQL changes, streams through Kafka with schemas enforced by Apicurio Registry (CNCF sandbox), and lands in Apache Iceberg tables queryable within seconds via Trino. Automatic schema evolution flows from database ALTER TABLE through Debezium and Apicurio to Iceberg DDL updates without manual intervention.

You'll see a column added in PostgreSQL propagate automatically to the Iceberg table and how Iceberg time-travel queries enable ML reproducibility. All components run on Kubernetes with Strimzi for Kafka, deployed with standard Kubernetes manifests.

Session format:
Session (35 minutes)

Tags:
Data, Platform Engineering, Open Source

Benefit to the cloud native community:
Demonstrates integration of CNCF projects (Apicurio Registry sandbox, Strimzi for Kafka) with Apache Iceberg for streaming lakehouse architecture. Shows real-world schema governance for data platforms on Kubernetes. The architecture addresses the common problem of batch ETL latency without introducing vendor lock-in. Fully reproducible with open source components and Kubernetes-native deployment.

Additional notes:
Demo code at github.com/carlesarnal/debezium-ocp-etc-demo with full Kubernetes deployment manifests. All components (Debezium, Strimzi, Apicurio Registry, Iceberg, Trino) run on Kubernetes.


SUBMISSION 2: Zero-Trust Security
----------------------------------

Session Title:
Zero-Trust Data Platforms: Unifying Kafka, Schema Registry, and Application Security with Keycloak

Description:
Your Kafka cluster uses one auth mechanism. Your schema registry uses another. Your applications use a third. Each component is secured individually but the gaps between them are where breaches happen.

This session demonstrates Keycloak integration with Strimzi (Kafka on Kubernetes) and Apicurio Registry (CNCF sandbox) for unified zero-trust security. OAuth2/OIDC replaces fragmented credentials, mutual TLS enforces identity across every connection, and fine-grained authorization controls who can produce consume and evolve schemas, all from a single identity provider.

Live demo: Keycloak realm setup, Kafka OAuth2 listeners, Apicurio OIDC integration, client credential flows. You'll see exactly where teams get this wrong (works in dev fails in prod) and how to avoid those configuration pitfalls.

Session format:
Session (35 minutes)

Tags:
Security, Platform Engineering, Open Source

Benefit to the cloud native community:
Shows production-ready security integration between Keycloak, Strimzi, and Apicurio Registry (CNCF sandbox), three projects commonly deployed together on Kubernetes but rarely shown with unified auth. Provides a deployable reference architecture for securing Kubernetes-native data platforms with zero-trust principles. Addresses credential sprawl and configuration complexity that plague multi-component data platforms.

Additional notes:
Full Kubernetes manifests and Keycloak configuration at github.com/carlesarnal/keycloak-strimzi-apicurio-security. Demo shows OAuth2 token flows, ACL enforcement, and registry authentication live.


SUBMISSION 3: Agent Discovery
------------------------------

Session Title:
From Schema Registry to Agent Registry: Governing AI Discovery with the A2A Protocol

Description:
As organizations adopt AI agents they're rediscovering the governance crisis that microservices faced. One team updates a prompt template or model schema and downstream agents silently break. Discovery versioning and compatibility, the same problems we solved for REST APIs, now apply to AI agents.

This talk shows how Apicurio Registry (CNCF sandbox) evolved to manage AI-native artifacts: A2A Agent Cards for discovery, LLM Model Schemas for metadata, and prompt templates with version control. Live demo: agents discovering each other through the A2A Protocol backed by registry-enforced compatibility rules that catch breaking changes before production.

You'll see agent cards registered agents discover each other and the registry reject incompatible version pushes. This brings proven schema governance patterns from the microservices era to multi-agent AI systems running on Kubernetes.

Session format:
Session (35 minutes)

Tags:
Platform Engineering, Open Source, Artificial Intelligence

Benefit to the cloud native community:
Demonstrates how CNCF sandbox project Apicurio Registry extends schema governance to AI agent ecosystems. Shows practical A2A Protocol integration with Kubernetes infrastructure. Addresses the emerging problem of agent sprawl in cloud-native environments with proven governance patterns. Helps teams adopt AI agents without repeating the microservices governance mistakes.

Additional notes:
Demo code at github.com/carlesarnal/agent-discovery-demo with A2A agent cards and prompt template versioning. All running on Kubernetes with registry governance.
