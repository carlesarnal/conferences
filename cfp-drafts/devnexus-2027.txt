SUBMISSION 1: Data Contracts for AI
------------------------------------

Title:
Why Your AI Pipeline Broke at 3 AM: Data Contracts for Event-Driven Machine Learning

Session Type:
Regular Session (50 minutes)

Abstract:
45% of enterprise AI projects fail because of data quality issues -- not model accuracy. The root cause is deceptively simple: producers and consumers in streaming AI pipelines evolve independently, and without formal contracts, a silent schema change in one team's Kafka producer becomes a 3 AM page for another team's inference service.

This talk shows how to apply data contracts to event-driven AI architectures -- the same discipline that API contracts brought to microservices, now enforced at the streaming layer. In a live demo with Debezium CDC, Kafka, and a downstream ML inference service built with Quarkus, I'll walk through how schema compatibility rules catch breaking changes at produce time, not at prediction time.

Takeaways: concrete pattern for data contracts in streaming AI, schema evolution strategies (Avro, Protobuf, JSON Schema) for Java developers, reproducible Kubernetes deployment.

Audience Level:
Intermediate

Tags:
Java, Kafka, AI/ML, Event-Driven Architecture, Quarkus


SUBMISSION 2: Real-Time Lakehouse
----------------------------------

Title:
Kill the Nightly Batch: Building a Real-Time Lakehouse with CDC, Kafka, and Apache Iceberg

Session Type:
Regular Session (50 minutes)

Abstract:
Batch ETL runs nightly. Analysts query stale data. ML models train on yesterday's features. The streaming-first lakehouse replaces all of that with a single, real-time pipeline built entirely with open-source tools on Kubernetes.

In a live demo, I'll build a complete pipeline end to end: Debezium captures row-level changes from PostgreSQL, streams them through Kafka with schema enforcement, and lands them in Apache Iceberg tables -- queryable within seconds via Trino or Spark. I'll show how Flink's Dynamic Iceberg Sink handles automatic schema evolution, eliminating the manual DDL changes that plague traditional data lakes. All components are Java-based and open source.

Audience Level:
Intermediate

Tags:
Java, Kafka, Apache Iceberg, Data Engineering, Kubernetes


SUBMISSION 3: Agent Discovery
-------------------------------

Title:
Agent Sprawl Is the New Microservice Sprawl: Discovery and Governance for Multi-Agent AI

Session Type:
Regular Session (50 minutes)

Abstract:
Five teams. Twenty agents. Three frameworks. No one knows which agents talk to which -- or what happens when one team's update silently breaks four downstream consumers. This is the same discovery and compatibility crisis that hit APIs a decade ago, except agents evolve faster and fail more quietly.

In a live demo, I'll apply proven registry-based governance patterns to AI agents using the A2A Protocol. You'll see agents publishing discoverable Agent Cards, negotiating capabilities at runtime, and failing fast on breaking changes -- before reaching production. The demo uses Java tooling throughout -- Quarkus agents, Java registry client, and standard REST APIs.

Audience Level:
Intermediate

Tags:
Java, AI Agents, A2A Protocol, Governance, Quarkus
