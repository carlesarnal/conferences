SUBMISSION 1: ML Pipeline on Kubernetes
----------------------------------------

Session Title:
Real-Time Content Classification on Kubernetes: An End-to-End Open Source ML Pipeline

Description:
Real-time data processing is critical in domains like finance, social media, and cybersecurity. In this talk I'll present a fully open source end-to-end system for real-time content classification deployed on Kubernetes. Using Reddit flair classification as a case study, the pipeline combines Apache Kafka for ingestion, Apache Spark Streaming for low-latency processing, and a machine learning model for classification, with predictions exposed through a Quarkus-based API.

This session goes beyond architecture to show the system in action: how Reddit posts are streamed into Kafka, classified in Spark, and served via microservices. I'll also cover practical deployment aspects on Kubernetes: scaling, monitoring, and extending the pipeline to other event-classification tasks. Attendees will gain hands-on insights into building and operating streaming ML systems on Kubernetes using only open source technologies.

Session format:
Session (35 minutes)

Tags:
Data, Platform Engineering, Open Source

Benefit to the cloud native community:
Demonstrates production-grade ML infrastructure using cloud-native projects: Strimzi for Kafka, Apicurio Registry (CNCF sandbox) for schema governance, and OpenTelemetry for observability. Shows how to operationalize ML on Kubernetes beyond just model serving, addressing real challenges teams face when deploying streaming ML at scale. The architecture is fully reproducible and uses only open source components, enabling attendees to deploy similar systems immediately.

Additional notes:
All demo code is open-source at github.com/carlesarnal/reddit-realtime-classification. The talk includes live demo of the full pipeline running on Kubernetes with metrics and tracing visible in real-time.


SUBMISSION 2: Security Integration
-----------------------------------

Session Title:
Zero-Trust Data Platforms: Unifying Kafka, Schema Registry, and Application Security with Keycloak

Description:
Your Kafka cluster uses one auth mechanism. Your schema registry uses another. Your applications use a third. Each component is secured individually but the gaps between them are where breaches happen.

This session demonstrates Keycloak integration with Strimzi (Kafka on Kubernetes) and Apicurio Registry (CNCF sandbox) for unified zero-trust security. OAuth2/OIDC replaces fragmented credentials, mutual TLS enforces identity across every connection, and fine-grained authorization controls who can produce, consume, and evolve schemas, all from a single identity provider.

Live demo: Keycloak realm setup, Kafka OAuth2 listeners, Apicurio OIDC integration, and client credential flows. You'll see exactly where teams get this wrong (works in dev fails in prod) and how to avoid those pitfalls with proper configuration.

Session format:
Session (35 minutes)

Tags:
Security, Platform Engineering, Open Source

Benefit to the cloud native community:
Shows production-ready security integration between Keycloak, Strimzi, and Apicurio Registry (CNCF sandbox), three projects commonly deployed together on Kubernetes but rarely shown with unified auth. Provides a deployable reference architecture for securing Kubernetes-native data platforms with zero-trust principles. Addresses the real-world problem of credential sprawl in cloud-native data infrastructure.

Additional notes:
Demo includes full Kubernetes manifests and Keycloak configuration at github.com/carlesarnal/keycloak-strimzi-apicurio-security. All components run on Kubernetes with proper TLS and OAuth2 flows demonstrated live.
