SUBMISSION 1: Agent Discovery / Governance
-------------------------------------------

Title: Agent Sprawl Is the New Microservice Sprawl: Discovery and Governance for Multi-Agent AI

Description (under 1000 characters):
Five teams. Twenty agents. Three frameworks. No one knows which agents talk to which -- or what happens when one team's update silently breaks four downstream consumers. This is the same discovery and compatibility crisis that hit APIs a decade ago, except agents evolve faster and fail more quietly.

I'll demonstrate publishing, discovering, and versioning A2A Agent Cards in a registry, then show how communication schemas can be checked independently. We'll distinguish metadata discovery from runtime negotiation and structural compatibility from behavioral correctness. Integration tests are still needed when an agent's behavior changes without changing its advertised interface.

Takeaways:
- A governance architecture for agent discovery, versioning, and deprecation using A2A Agent Cards
- Patterns for enforcing compatibility rules across independently evolving agents
- Where A2A, MCP, and traditional API governance overlap and diverge

Submitting for: KubeCon + CloudNativeCon
Poster Session: No
Track: AI + ML (or AI Inference + Agentic if available)
Session format: Session Presentation
Audience Level: Intermediate
Case study: No
Talk presented before: Confirm actual delivery and overlap with earlier agent-discovery talks; do not infer delivery from acceptance.
Relevant CNCF/Open Source Projects: Apicurio Registry (CNCF Sandbox), Kubernetes
Additional resources: https://github.com/carlesarnal/agent-discovery-demo

Value to the community:
Multi-agent AI systems are scaling faster than the governance tooling around them. Without discovery and compatibility contracts, organizations face the same cascading failure patterns that plagued ungoverned microservices -- but with faster iteration cycles and more silent failures. This talk gives the cloud-native community a concrete, protocol-based governance model using the A2A standard, built on proven schema registry patterns that CNCF practitioners already understand. It directly addresses the growing intersection of AI infrastructure and cloud-native operations.


SUBMISSION 2: CNCF Sandbox Journey
------------------------------------

Title: So You Want to Join the CNCF: A Maintainer's Honest Guide to the Sandbox Process

Description (≤1000 chars):
What does applying to the CNCF Sandbox involve from the maintainer's side? I'll share my experience participating in Apicurio Registry's submission and explain how to prepare a project's application.

We'll discuss documenting governance, licensing, contribution processes, and project scope; finding the current submission requirements; and planning for ongoing maintenance. I'll distinguish lessons from our application from general advice, without treating acceptance as a guarantee of adoption, contributor growth, or funding.

Takeaways:
- A realistic, step-by-step roadmap for submitting a project to the CNCF Sandbox
- The governance, licensing, and community structure decisions foundations actually evaluate
- An honest assessment of benefits and new obligations

SUBMISSION 3: Real-Time Lakehouse
----------------------------------

Title: Kill the Nightly Batch: Building a Real-Time Lakehouse with CDC, Kafka, and Apache Iceberg

Description (≤1000 chars):
Batch ETL runs nightly. Analysts query stale data. ML models train on yesterday's features. The streaming-first lakehouse replaces all of that with a single real-time pipeline built entirely with open-source tools on Kubernetes.

I'll demonstrate a CDC-to-lakehouse pipeline using Debezium, Kafka, Flink, and Apache Iceberg. We'll examine a supported schema evolution and a breaking change, and discuss how registry checks, checkpoints, and table commits affect compatibility and query freshness. Schema checks do not validate all data-quality or semantic changes.

Takeaways:
- A deployable CDC-to-Iceberg pipeline using only open-source components on Kubernetes
- Practical patterns for schema evolution across the Kafka-to-Iceberg boundary
- When streaming lakehouse replaces batch ETL and where hybrid patterns still win

Submitting for: KubeCon + CloudNativeCon
Track: Application Development (or Data + AI)
Session format: Session Presentation
Audience Level: Intermediate
Case study: No

Additional resources: https://github.com/carlesarnal/database-to-lakehouse-demo

Value to the community:
Real-time data infrastructure is increasingly deployed on Kubernetes, but most CDC-to-lakehouse architectures rely on proprietary cloud services. This talk demonstrates a fully open-source, cloud-native alternative using CNCF and Apache ecosystem projects, giving practitioners a reproducible blueprint for building streaming lakehouses without vendor lock-in. Schema evolution across streaming boundaries is a persistent pain point -- the patterns shown here address it directly.
