1. AGENTICS DAY: MCP + AGENTS
================================================================
Topics listed include: Building MCP Servers & Clients; Security, Trust &
Reliability; Enterprise Integration & Governance.

Title:
A2A or MCP? Choosing an Interface for the Same Capability

Description:
The same summarization service can accept text and return a summary through
MCP or A2A. The useful comparison begins when the caller needs task progress
or receives a failed invocation. What does each interface let the caller know?

Holding the capability constant, Quarkus examples trace a successful request
and a failure through the caller contract. A compact decision table separates
protocol support, advertised behavior and tested behavior for pinned versions.
Task state and failure handling are the core examples; cancellation and
authorization become selection questions rather than separate demos. Attendees
learn when either interface, or both, meets their requirements.

Benefits to the ecosystem:
A same-capability comparison helps MCP practitioners reason about integration
choices without treating tools as inherently simple or agents as inherently
intelligent. The decision table makes lifecycle and failure requirements explicit.

Differs from the KubeCon EU submission: interface selection for one capability,
rather than registry-backed discovery and card compatibility. The historical
submitted EU version also mentioned deprecation; the current demo does not.

CNCF projects: Apicurio Registry (sandbox). Other: MCP, A2A.
Case study: No.

Preparation (not form text): the Paris-branch demo exercised A2A agents and an
MCP weather server. It does NOT yet expose the same capability both ways.
Implement and test the paired comparison and its decision table.

2. KEYCLOAKCON
================================================================
Topics listed include: Securing Applications and Cloud Native Infrastructure
with Keycloak; Keycloak Security Best Practices.

Title:
One Keycloak Realm, Separate Trust Boundaries: Securing Kafka and Its Schema Registry

Description:
A producer can have permission to publish Kafka records without permission to
change their schemas. How do you diagnose a denied operation without expanding
privileges until it works? One Keycloak realm does not make Kafka and registry
permissions interchangeable.

Three cases change one condition at a time: an invalid token, a valid identity
denied a Kafka operation, and a valid identity denied a schema mutation. Each
pairs a denial with a successful control and identifies the enforcing component.
Attendees get a symptom/evidence/action table covering token validation,
principal mapping, Kafka ACLs and registry permissions. Key rotation is backup
discussion so the 25-minute session can focus on the diagnostic method.

Benefits to the ecosystem:
Keycloak is frequently deployed in front of Kafka and schema registries, but
the boundaries between authentication and each component's authorization are
rarely shown together. This gives Keycloak users a reusable map of those
boundaries and practical checks for them.

CNCF projects: Keycloak (incubating), Strimzi (incubating), Apicurio Registry (sandbox).
Case study: No.

denial, HTTP on some paths). Same gaps as the NDC Security package; fix once

3. CLOUD NATIVE AI + INFERENCE DAY
================================================================
Topics listed include: LLMs & Generative AI; End-to-End AI/ML in Production.

Title:
Beyond Git: Releasing and Rolling Back Runtime Prompt Templates

Description:
The prompt was reverted in Git; a running service still uses the newer version.
This session follows source revision, Apicurio Registry artifact and explicit
template selection in a Quarkus/LangChain4j consumer to explain the gap.

A structural check tests a changed required-variable contract; a small evaluation
set with predeclared criteria assesses an instruction-only change. We distinguish
rejecting a candidate from rolling back an already selected version, accounting
for consumer refresh and caching. Attendees get a release checklist and criteria
for choosing runtime distribution versus an ordinary application release.

Benefits to the ecosystem:
The workflow separates authoring and review in Git from runtime distribution,
and template compatibility from output evaluation. It helps teams design
controlled prompt releases without assuming schemas guarantee answer quality.

CNCF projects: Apicurio Registry (sandbox).

Preparation (not form text): earlier scripts exercised registration and template
compatibility. Evaluation, consumer version selection, caching and rollback
still need an end-to-end check. See talks/PREPARATION.txt.
