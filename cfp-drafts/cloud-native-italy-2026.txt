SUBMISSION 1: Edge to Cloud CDC
--------------------------------

Session Title:
From Edge to Cloud: Building Real-Time Data Pipelines with Debezium, Kafka, and Apicurio on Kubernetes

Description:
A row changes in PostgreSQL at the edge. Milliseconds later an Elasticsearch index in the cloud reflects that change, no batch jobs, no polling, no glue code. This talk shows how to build that pipeline using only open-source components on Kubernetes.

Live demo walkthrough: Debezium captures database changes, Apicurio Registry (CNCF sandbox) enforces schemas, Kafka on Strimzi streams Avro-serialized events, and Kafka Streams with Quarkus processes them to sync Elasticsearch with sub-second latency.

I've presented this architecture at Current, Data Saturday, and other conferences since 2023. This version incorporates lessons from real-world deployments and shows how Apicurio's CNCF acceptance strengthened the cloud-native integration. You'll see schema evolution in action, compatibility enforcement, and the full pipeline deployed on Kubernetes.

Session format:
Session (35 minutes)

Tags:
Data, Platform Engineering, Open Source

Benefit to the cloud native community:
Demonstrates integration of CNCF projects (Apicurio Registry sandbox, Strimzi for Kafka) for real-time CDC pipelines on Kubernetes. Shows practical schema governance patterns that prevent breaking changes in production. The architecture is battle-tested, fully open source, and addresses the common need to sync data across systems without batch ETL. All components are Kubernetes-native.

Additional notes:
Demo code at github.com/carlesarnal/debezium-ocp-etc-demo with full Kubernetes manifests. Presented at multiple conferences since 2023 with continuous refinement.


SUBMISSION 2: Kafka Proxy Validation
-------------------------------------

Session Title:
Transparent Schema Validation at the Kafka Proxy Layer with Kroxylicious

Description:
Schema validation usually happens at the producer client but what about legacy producers you can't modify, third-party integrations, or teams that skip validation? The schema-invalid messages still reach Kafka and by then the damage is done.

This session introduces a different approach: enforcing schema validation transparently at the Kafka proxy layer using Kroxylicious. I'll demo a setup where a Kroxylicious filter intercepts produce requests, validates payloads against schemas stored in Apicurio Registry (CNCF sandbox), and rejects non-compliant messages before they ever reach the broker, without any producer code changes.

You'll see invalid JSON rejected at the proxy and valid messages forwarded to Kafka. This is infrastructure-layer data quality enforcement for Kubernetes-native Kafka deployments.

Session format:
Session (35 minutes)

Tags:
Platform Engineering, Data, Open Source

Benefit to the cloud native community:
Shows how to enforce data quality policies on producers you don't control using Kroxylicious proxy with Apicurio Registry (CNCF sandbox). Addresses the gap in schema validation for legacy systems, third-party integrations, and multi-tenant Kafka on Kubernetes. Provides a deployable pattern for transparent policy enforcement at the infrastructure layer.

Additional notes:
Demo code at github.com/carlesarnal/kroxylicious-schema-validation with Kubernetes deployment and filter configuration.


SUBMISSION 3: CNCF Sandbox Journey
-----------------------------------

Session Title:
From Community Project to CNCF Sandbox: What We Learned Bringing Apicurio Registry to the Foundation

Description:
Getting accepted into the CNCF Sandbox is a milestone but the months of governance restructuring, community alignment, and technical changes that precede it are rarely discussed publicly. This talk pulls back the curtain on what the journey actually looks like from a maintainer's perspective.

I'll walk through the concrete steps we took to bring Apicurio Registry into the CNCF: aligning governance with foundation expectations, adapting our contribution model, navigating due diligence, and the technical changes to meet cloud-native standards. I'll also cover what changed after acceptance in contributor engagement, project visibility, and new responsibilities.

This isn't a clean success story. I'll cover the governance debates, the features we deprioritized to meet cloud-native standards, and the cultural shift from corporate-backed to foundation-hosted community.

Session format:
Session (35 minutes)

Tags:
Open Source, Platform Engineering

Benefit to the cloud native community:
Provides realistic roadmap for other projects considering CNCF submission. Shares lessons on governance and community structure that foundations look for. Gives honest assessment of benefits and new responsibilities that come with CNCF membership. Helps demystify the sandbox acceptance process and sets realistic expectations.

Additional notes:
As an Apicurio Registry maintainer who participated in the CNCF submission, I can provide behind-the-scenes insights, not marketing.
