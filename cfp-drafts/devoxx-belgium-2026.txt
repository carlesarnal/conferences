SUBMISSION 1: Data Contracts for AI (for Deep Dive track)
----------------------------------------------------------

Title:
Data Contracts for Event-Driven AI: How Schema Registries Prevent Pipeline Failures

Session Type:
Deep Dive (50 minutes)

Abstract:
45% of enterprise AI projects fail on data quality not model accuracy. The root cause? Silent schema changes. A Kafka producer evolves its schema and downstream ML inference services crash at 3 AM.

This session demonstrates how data contracts enforced through Apicurio Registry (CNCF sandbox) bring the same discipline to AI pipelines that API contracts brought to microservices. Live demo with Debezium CDC, Kafka on Strimzi, Apicurio Registry, and an ML inference service. You'll see the registry catch breaking changes at produce time not at prediction time.

I'll compare schema evolution strategies (Avro, Protobuf, JSON Schema) and show when each fits AI workloads. I'll cover the Kafka integration patterns, the Avro serializers, and how to deploy this on Kubernetes. The demo is fully open-source, written in Java, and deployable.

Takeaways: concrete pattern for data contracts in event-driven AI, schema format guidance for Java developers, reproducible setup for Kubernetes deployment.

Audience Level:
Intermediate/Advanced

Tags:
Kafka, Java, AI/ML, Event-Driven Architecture, Kubernetes


SUBMISSION 2: Edge to Cloud (for Tools in Action track)
--------------------------------------------------------

Title:
From Edge to Cloud: Building Real-Time Data Pipelines with Debezium, Kafka, and Apicurio on Kubernetes

Session Type:
Tools in Action (30 minutes)

Abstract:
A row changes in PostgreSQL at the edge. Milliseconds later an Elasticsearch index in the cloud reflects it, no batch jobs, no polling. In this hands-on demo I'll show exactly how to build that pipeline using only open-source Java tools on Kubernetes.

Live walkthrough: Debezium for CDC, Apicurio Registry (CNCF sandbox) for schema enforcement, Kafka on Strimzi for event streaming, and Quarkus for stream processing. You'll see data flow from PostgreSQL to Elasticsearch with sub-second latency, schema evolution with Avro, and how it all deploys on Kubernetes.

This is a working reference architecture I've refined at Current, Data Saturday, and other conferences since 2023. Every component shown is open-source Java-based tooling.

Audience Level:
Intermediate

Tags:
Kafka, Quarkus, CDC, Kubernetes, Event-Driven Architecture


SUBMISSION 3: Kafka Proxy Validation (for Conference track)
------------------------------------------------------------

Title:
Transparent Schema Validation at the Kafka Proxy Layer with Kroxylicious

Session Type:
Conference Session (45 minutes)

Abstract:
Schema validation usually happens at the producer client but what about legacy producers you can't modify, third-party integrations, or teams that skip validation? The schema-invalid messages still reach Kafka and by then the damage is done.

This session introduces Kroxylicious, a protocol-aware Kafka proxy written in Java. I'll demo a setup where a Kroxylicious filter intercepts produce requests, validates payloads against schemas stored in Apicurio Registry (CNCF sandbox), and rejects non-compliant messages before they reach the broker, without any producer code changes.

You'll see invalid JSON rejected at the proxy and valid messages forwarded to Kafka. I'll cover the filter implementation, the registry integration, and deployment patterns on Kubernetes.

Audience Level:
Intermediate

Tags:
Kafka, Java, Kroxylicious, Schema Validation, Infrastructure


SUBMISSION 4: Agent Discovery (for Conference track)
-----------------------------------------------------

Title:
From Schema Registry to Agent Registry: Governing AI Discovery with the A2A Protocol

Session Type:
Conference Session (45 minutes)

Abstract:
As Java shops adopt AI agents they're rediscovering the governance crisis that microservices faced. One team updates a prompt template and downstream agents silently break.

This talk shows how Apicurio Registry (CNCF sandbox, written in Java/Quarkus) evolved to manage AI-native artifacts: A2A Agent Cards, LLM Model Schemas, and prompt templates. Live demo: agents discovering each other through the A2A Protocol backed by registry-enforced compatibility rules.

You'll see agent cards registered via REST API, agents discover peers using the same patterns as schema discovery, and the registry reject incompatible version pushes. This brings proven schema governance patterns to multi-agent AI systems.

Audience Level:
Intermediate

Tags:
AI, Java, Governance, A2A Protocol, Quarkus
