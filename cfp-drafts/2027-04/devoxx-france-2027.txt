SUBMISSION 1: Data Contracts for AI (Conference track)
-------------------------------------------------------

Title:
Your Model Didn't Change, Your Input Did: Data Contracts for Streaming AI Pipelines

Session Type:
Conference (45 minutes)

Abstract:
Producers and consumers in streaming AI pipelines evolve independently. Without explicit data contracts, an upstream schema change can break a downstream inference service even when the model has not changed.

This talk shows how to apply data contracts to event-driven AI architectures. In a live demo with Debezium CDC, Kafka, and a downstream ML inference service, I'll walk through how schema compatibility rules catch breaking changes at produce time, not at prediction time. I'll compare schema evolution strategies (Avro, Protobuf, JSON Schema) and show when each fits ML workloads. Fully open-source, reproducible on Kubernetes.

Audience Level:
Intermediate

Tags:
Java, Kafka, AI/ML, Architecture, Quarkus


SUBMISSION 2: Real-Time Lakehouse (Tools in Action track)
----------------------------------------------------------

Title:
The Sink Said RUNNING: Building a CDC-to-Iceberg Pipeline on Kubernetes, Honestly

Session Type:
Tools in Action (30 minutes)

Abstract:
Batch ETL runs nightly. Analysts query stale data. The streaming-first lakehouse replaces all of that with one real-time pipeline. In a live demo, I'll build it end to end: Debezium captures row-level changes from PostgreSQL, streams them through Kafka with schema enforcement, and lands them in Apache Iceberg tables -- queryable within seconds via Trino or Spark. I'll show how Flink's Dynamic Iceberg Sink handles automatic schema evolution, eliminating the manual DDL that plagues traditional data lakes.

Audience Level:
Intermediate

Tags:
Java, Kafka, Apache Iceberg, Kubernetes, Tools


SUBMISSION 3: Kafka Proxy (Conference track)
---------------------------------------------

Title:
Validate Before Kafka: What Happens When a Proxy Enforces Your Schemas

Session Type:
Conference (45 minutes)

Abstract:
Schema validation usually happens at the producer client -- but what about legacy producers you can't modify, third-party integrations, or teams that skip validation? Those schema-invalid messages still reach Kafka, and by the time a consumer fails on bad data, the damage is done and the offset has moved.

In this session, I'll demo enforcing schema validation transparently at the proxy layer using Kroxylicious. A proxy filter intercepts produce requests, validates payloads against a schema registry, and rejects non-compliant messages before they ever reach the broker -- with zero changes to producer code. I'll cover the Java filter implementation and deployment on Kubernetes.

Audience Level:
Intermediate

Tags:
Java, Kafka, Kroxylicious, Architecture


Speaker Bio:
