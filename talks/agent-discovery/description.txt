Title: Agent Sprawl Is the New Microservice Sprawl: Discovery and Lifecycle for Multi-Agent AI

Five teams, twenty agents, three frameworks. Nobody knows which agent depends on which, and a "minor update" that drops a skill breaks its callers without an error. Microservices went through the same thing; registries, contracts and lifecycle rules got them out of it.

This session applies those patterns to A2A agents and MCP tools, live, on open source. Quarkus agents publish their own A2A Agent Cards to Apicurio Registry (CNCF sandbox) on startup. An orchestrator discovers them, picks one per request and delegates over A2A; an MCP tool is found through the same registry. Then we break things: removing a skill from a card is rejected before it reaches anyone, and marking an agent DEPRECATED stops new traffic to it without a redeploy.

We'll also be precise about the limits found while building it: discovery is not capability negotiation, consumers that ignore deprecation keep calling, and a released card publisher kept stale cards after restarts (fixed upstream in quarkus-langchain4j).

Attendees will leave with:
- A working pattern for agent and tool discovery from a registry, without hardcoded URLs
- Compatibility rules that catch breaking Agent Card changes before production
- A lifecycle model (version, deprecate, retire) and what consumers must do for it to work
