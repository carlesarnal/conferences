Title: Validate Before Kafka: What Happens When a Proxy Enforces Your Schemas

Client-side schema validation only works if every producer is configured correctly. Legacy clients, third-party integrations and one misconfigured service are enough to put records on a topic that consumers cannot read.

This session moves validation into the path to the broker, using the Record Validation filter in Kroxylicious with schemas from Apicurio Registry (CNCF sandbox). Live: a valid order goes through; a missing field, a wrong type and an invalid enum value are rejected, and the producer gets an error naming the exact constraint.

Then the behavior nobody puts on the slide: one bad record rejects its whole batch, valid records included; a producer that connects to the broker directly skips validation entirely; and when the registry is down the filter fails closed, rejecting valid data with the same exception used for invalid data. We'll go through how to handle each one in producers and deployment.

Attendees will leave with:
- How a Kafka proxy filter intercepts and rejects produce requests
- When to validate in the client, the proxy, or both
- A checklist for batch failures, bypass paths and registry outages

Speaker contributed Avro and Protobuf validation to the Kroxylicious filter. Demo verified end to end on Kroxylicious 0.24.0.
