Title: A2A or MCP? Composing Agents and Tools Without Building a Distributed Monolith

Teams adopting agentic AI hit the same question early: should this capability be an A2A agent or an MCP tool? Get it wrong and you end up with agents that are really tools, tools that hide whole workflows, and a call graph nobody can trace.

This session compares the two protocols where it matters for design: who owns the reasoning, what the contract describes (Agent Card skills vs tool schemas), how each is discovered, and how each fails. Using one demo with A2A agents and an MCP server published in the same registry, we'll follow a request that delegates to an agent and one that calls a tool, then change each contract and see what breaks and what the registry catches.

Attendees will leave with:
- A decision guide for exposing a capability as an A2A agent or an MCP tool
- How discovery, versioning and failure differ between the two protocols
- Anti-patterns that turn multi-agent systems into distributed monoliths
