FINAL EDITORIAL CHECKS
----------------------
1. Contribution: name the decision or observation that makes the talk more than
   an integration overview. For proxy/lakehouse/agents, put the recorded behavior
   in the abstract; for unfinished experiments, describe the question honestly.
2. Evidence: attach an input, expected observation, actual observation and a
   reproducible path. A repository, title or count of tests alone is insufficient.
3. Boundary: state exactly what is checked. Metadata publication is not deployed
   behavior; process health is not data progress; structure is not feature meaning.
4. Contrast: include a simpler alternative and when it is enough. Static endpoints,
   application-bundled prompts and existing configuration are valid choices.
5. Scope: the headline, demo and takeaways must answer the same question. Put
   adjacent protocols, formats, models and roadmap features in backup material.
6. Evidence limits: retain measured conditions and implementation status. Avoid
   replacing a missing result with a promised metric or a broader guarantee.
