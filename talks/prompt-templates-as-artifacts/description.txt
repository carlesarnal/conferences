Title: Your Prompts Are Unversioned: Releasing and Rolling Back LLM Prompts Like Code

Prompt templates change application behavior as much as code does, yet most live in environment variables or hardcoded strings: no history, no review, no rollback when an "improved" prompt makes answers worse.

This session treats prompts as versioned artifacts. With Apicurio Registry (CNCF sandbox), we'll register and render templates, have a Quarkus + LangChain4j application load a selected version at runtime, and roll a change forward and back without a redeploy. Structural rules reject breaking changes such as removing a variable the template still uses or changing its type. And we'll be honest about the limit: a compatible prompt can still produce worse answers, so versioning has to be paired with evaluation tests.

Attendees will leave with:
- A release workflow for prompts: version, review, select, roll back
- Which prompt changes structural rules can catch, and which need evaluation
- When prompt governance is worth it and when it's overkill
