Title: The Sink Said RUNNING: Building a CDC-to-Iceberg Pipeline on Kubernetes, Honestly

Streaming database changes into Apache Iceberg looks like three components and a diagram. Building it on current releases took longer: metadata files corrupted on S3-compatible storage, a sink that reported RUNNING while committing nothing, and "real time" that turned out to depend on one setting most people never change.

In this session, we build the pipeline live with Strimzi, Debezium, Apicurio Registry (CNCF sandbox), the Apache Iceberg Kafka Connect sink and Trino. We time a new row from PostgreSQL into Iceberg (30-45 seconds with a 10-second commit interval; the default is five minutes), add a column and follow it through a new registry version to an evolved table, and query an append-only changelog for current state and past snapshots.

Attendees will leave with:
- A reproducible CDC-to-Iceberg pipeline on Kubernetes using only open source
- The settings that decide freshness, and the trade-offs of shortening them
- The failure modes we hit and how to detect them before your analysts do
